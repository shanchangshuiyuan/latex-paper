\chapter{数字工厂可视化系统设计与实现}
本章将前文提出的融合扫视时序特征的多维感知注视点渲染方法与基于时空视觉感知的动画网格混合LOD方法应用于实际工业场景，设计并实现一套完整的数字工厂可视化系统。
该系统集成了轻量级 Web 三维可视化与沉浸式 VR漫游双重交互模式，通过实际系统的构建与多维度测试，
验证了本文所提方法在保证视觉沉浸感与交互实时性的前提下，解决大规模、高复杂度工厂场景渲染效率瓶颈的可行性与有效性。
\section{系统开发与运行环境}

为保障系统运行的稳定性、实时性并满足高性能渲染算法的验证需求，本节详细阐述系统的软硬件开发配置。

系统采用前后端分离架构，核心计算平台采用高性能工作站，配置 Intel Core i7-12700K CPU 与 NVIDIA GeForce RTX 3090 GPU，辅以 32GB 高速内存，以确保满足高负荷图形计算与复杂数据处理的需求。
VR 交互端选用 HTC Vive Pro Eye 头显，该设备内置的 Tobii 眼动追踪模块能够提供毫秒级的视线数据采集，配合 SteamVR 2.0 基站，为注视点渲染算法提供精确的空间定位与实时视线输入支持。

前端可视化模块基于 Vue3 框架结合 Three.js 图形引擎构建，负责 Web 端的轻量化场景展示；
VR 沉浸漫游模块采用 Unity 2021.3 LTS 引擎开发，利用其可编程渲染管线深度集成融合扫视时序特征的多维感知注视点渲染方法及基于时空视觉感知的动画网格混合LOD方法。
后端服务层基于 Node.js 运行时环境与 Express 框架搭建，负责业务逻辑处理与数据通信。
数据持久层选用 MySQL 存储结构化业务元数据，InfluxDB 存储高频时序监控数据。

\section{数字工厂可视化系统设计}

本系统采用浏览器端/服务端/VR端的混合体系结构，数据处理与逻辑分发集中于服务端，浏览器端负责宏观场景的轻量化展示与管控，高保真的虚拟现实交互功能在 Unity 客户端中运行。

\subsection{系统功能需求分析}

本文设计的系统旨在解决工业数字孪生场景中高沉浸感与高渲染负载之间的矛盾，其功能架构设计需满足多维度感知、高实时性渲染与智能数据分析三大核心要求。
结合工业数字化技术与本文提出的核心算法，具体需求可归纳为以下方面：

（1）融合感知模型的动态渲染调度：系统需具备实时眼动数据流处理能力，依据 castleCSF-TS 模型动态评估用户在时空维度的视觉敏感度，驱动渲染管线实现分辨率与着色质量的自适应调节。

（2）支持动画网格的感知自适应LOD：针对机械臂、自动导引运输车（AGV）等动态工业设备，系统需集成基于时空视觉感知的动画网格混合LOD方法，根据注视点位置与感知权重，实现从离线网格简化到运行时曲面细分的全流程优化，在降低几何开销的同时减少视觉失真。

（3）跨平台双模式交互与数据联动：系统需提供Web 端轻量级概览与 VR 端沉浸式漫游两种交互模式。在网页端，侧重于工厂整体布局与关键指标的快速概览；在VR端，为用户提供身临其境的第一人称视角。无论用户处于何种模式，其交互操作如设备选中、指令下发均需通过服务端实现数据闭环，实时触发可视化面板的业务数据更新。

（4）全链路性能监测与评估：为验证算法有效性，系统需内置性能监控模块，实时采集帧率、GPU 负载、Draw Calls、眼动轨迹及各区域渲染开销，并支持与时序业务数据关联分析，为算法优化提供量化依据。

\subsection{系统架构设计}
为满足上述需求，系统采用分层微服务架构设计，如图\ref{fig:system-architecture}所示,整体架构分为渲染引擎层、应用层、服务中间层和数据持久层，各层级间通过标准化接口实现数据传递与功能协同。

（1）渲染引擎层：该层以Unity实时渲染引擎为框架，深度集成了本文提出的两项核心算法，构成了整个系统的图形处理中枢。该层独立负责VR场景的高保真渲染任务，通过WebSocket长连接与服务中间层进行毫秒级数据同步，实时获取设备状态并反馈用户交互事件。
在此层架构中，我们针对Unity的可编程渲染管线进行了定制开发：融合扫视时序特征的多维感知注视点渲染方法被实现为注视点渲染模块，该模块实时处理眼动追踪数据，基于castleCSF-TS感知模型动态生成分辨率缩放因子，指导渲染管线在像素着色阶段实施非均匀的多分辨率渲染；
基于时空视觉感知的动画网格混合LOD方法被构建为动态LOD模块，该模块接收来自注视点渲染模块的分辨率缩放因子和场景上下文信息，在GPU硬件支持下对动画网格实施感知驱动的自适应细分。
两模块协同工作，确保计算资源智能聚焦于视觉中央凹区域，实现性能与画质的最优平衡。

（2）应用层：该层直接面向终端用户提供差异化交互界面。
Web端使用 Vue 框架集成了可视化模块和漫游模块，侧重于工厂全景的轻量化展示与关键数据监控。
可视化模块采用 Three.js 引擎构建轻量级三维场景，结合八叉树空间分割算法实现模型实现视锥体剔除与分块加载，
并应用 LOD 技术根据观察距离动态切换模型精度，同时通过 ECharts 图表实时呈现工厂生产与能耗数据；
漫游模块则负责提供高保真的沉浸式交互体验，通过在 Vue 组件中嵌入 Unity WebGL 实例，并通过消息传递机制确保 Web 页面上的交互指令能实时同步至 VR 场景，同时将 VR 中的渲染状态反馈至前端界面。

（3）服务中间层：本层作为系统的业务中枢与数据桥梁，基于Node.js微服务架构构建。
其职责包括：通过OPC UA、Modbus等工业协议对接物理车间的数据源，将采集到的设备状态、传感器读数等实时信息进行聚合、清洗与转换；
通过RESTful API为Web前端提供结构化的历史数据查询服务；
通过专用的WebSocket服务与VR渲染引擎保持双向、低延迟的实时数据通道，同步设备状态与交互指令；
此外，该层还统一管理用户认证、会话状态及跨端数据同步，确保Web与VR体验间状态的一致性，为上层应用提供稳定、高效的数据服务支撑。

（4）数据持久层：该层为系统提供统一、可靠的数据持久化支持，采用多类型数据库混合存储方案。
关系型数据库MySQL负责存储工厂模型元数据、用户信息、业务配置等结构化数据；
时序数据库InfluxDB负责存储设备实时运行参数与渲染性能指标等时序数据；文件系统用于管理高精度纹理与模型资产。

\section{核心模块实现与算法集成}
数字工厂可视化系统主要由可视化模块、漫游模块、数据通信与监控模块组成，共同构建起虚实结合的工业监控体系。本节将详细阐述系统的关键模块实现细节并重点阐述本文所提两大核心技术的集成方式。

\subsection{可视化模块}
可视化模块为数字工厂可视化系统中用户交互的核心载体，根据数据类别分为工厂信息可视化和工厂模型可视化，实现了工厂全景的轻量化展示与虚实数据的有机整合，模块框架如图\ref{fig:system-visualization-module}所示。

    \caption{系统可视化模块图}
    \label{fig:system-visualization-module}
\end{figure}

在模型可视化层面，系统采用 Three.js 引擎构建轻量化 WebGL 渲染场景。为解决大规模场景在浏览器端的加载瓶颈，模块结合八叉树空间索引算法实现静态模型的按需加载，并利用 LOD 技术根据视点距离动态切换模型精度，确保浏览流畅性。

在信息可视化层面，基于 Vue3 框架集成 ECharts 组件库构建动态数据监控面板，以 2D 叠加层的形式悬浮于三维场景之上，通过事件驱动机制实现模型-数据的双向绑定:
当用户在三维场景中通过射线检测选中特定设备时，系统将自动捕获对象 ID 并调用 RESTful API 获取实时运行参数，随即触发信息面板的数据更新或在场景中自适应渲染 3D 信息标签，实现所见即所得的交互体验。

此外，该模块兼具轻量级监控与沉浸式入口的双重职能，既负责宏观数据的快速概览，也为 Unity 漫游模块提供基础场景索引与数据通道，主要的渲染优化算法则将在接下来的 VR 漫游模块中重点验证。

\subsection{漫游模块}

漫游模块为数字工厂可视化系统提供多维度、多模式的空间探索能力，支持桌面端非沉浸式交互与 VR 端沉浸式漫游的双模式切换，是验证本文核心算法有效性的核心实验载体。模块框架如图\ref{fig:system-roaming-module}所示。

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.75\linewidth]{../figures/fiveChapter/漫游模块.png}
    \caption{系统漫游模块图}
    \label{fig:system-roaming-module}
\end{figure}

在VR沉浸式体验场景下，系统基于 Unity 引擎构建了一套独立且深度定制的高性能渲染管线，实现了两项核心优化技术的无缝集成与协同调度。

该渲染管线的运行始于实时数据的获取与处理：系统通过HTC Vive Pro Eye头显内置的眼动追踪模块捕获用户原始的视线数据，利用眼动事件检测算法精准识别
扫视开始、扫视着陆等关键时序节点，从而界定当前的视觉感知窗口。此时间域信息连同场景亮度、空间频率等环境特征，
被共同输入至预置的 castleCSF-TS 感知模型，实时计算出当前用户在时空维度上的对比度敏感阈值，生成指导全局渲染资源分配的核心感知参数。

在像素处理阶段，系统应用融合扫视时序特征的多维感知注视点渲染方法（注视点渲染模块）：依据感知模型输出的参数，渲染管线动态地为屏幕不同区域分配不同的渲染分辨率，
在扫视及随后的视觉敏感度恢复期内，中央凹及周边区域的分辨率将被显著、平滑地调低；
当进入稳定注视期后，则逐步恢复至全分辨率渲染，同时保持周边视觉区域的低分辨率采样，以此在时间与空间域上双重剔除了无效的着色计算。

在几何处理阶段，系统应用基于时空视觉感知的动画网格混合LOD方法（动态LOD模块）：针对机械臂等复杂动画网格，
渲染管线采用粗粒度选择加细粒度细分的混合策略： 首先，根据注视点距离与模型屏幕占比，从预处理的离散 LOD 库中快速筛选出基础几何体； 
随后，将基础网格与感知参数传递至 GPU 曲面细分着色器，驱动硬件对网格进行实时、自适应的细化。
该策略确保了位于注视焦点且运动缓慢的区域获得极高的几何细节，而外围或快速运动区域保持精简，并通过平滑过渡算法避免了层级切换时的视觉突变。

通过上述技术的集成，该模块在VR设备上实现稳定且流畅漫游体验，并具备对用户眼动轨迹、交互行为及渲染性能数据的同步采集能力，为后续的算法效能分析提供了坚实的数据基础。


\subsection{数据通信与监控模块}
数据通信与监控模块是数字工厂可视化系统中连接物理车间与虚拟空间的数据桥梁，也是确保系统功能闭环运行与量化评估本文渲染优化算法效能的核心工具。

在实时数据通信方面，模块采用 WebSocket 协议在客户端与服务层之间建立了持久化的双向通信链路，实现了虚实系统的闭环控制：
物理工厂侧的实时运行数据包括产线设备状态、各类传感器读数等被持续推送至webGL和Unity渲染引擎，驱动虚拟场景中对应三维实体的动态更新如设备运转动画及报警状态指示等，确保数字孪生体的实时性。
同时，用户在web端与VR沉浸环境中的所有交互意图如通过手柄点选设备、调整参数、触发操控指令等，也通过同一通道实时上行至服务层，继而触发现实控制系统或业务逻辑的响应，完成了从用户感知到场景更新的完整闭环。

在算法效能评估方面，为了在不干扰渲染主线程的前提下精确采集性能数据，模块深度集成Unity Profiling API并封装了轻量级性能计数器，对渲染管线的运行状态进行全方位监控。
采集的指标维度包括：渲染帧时间分布、GPU各阶段处理耗时、各分辨率区域的像素填充统计、动画网格LOD切换频率及细分因子分布情况等。所有这些性能数据与精确的时间戳、当前注视点坐标等信息一并打包，通过独立的低优先级WebSocket数据通道传输至服务层，最终持久化存储到时序数据库InfluxDB中。

该模块通过数据管道与Unity引擎、前端界面同步，不仅保障了数字工厂的稳定运行，更为渲染算法效能评估提供了可靠的数据支撑。

\subsection{系统测试}
为全面验证本文提出的数字工厂可视化系统的性能表现及核心算法的有效性，本研究设计了覆盖基础功能验证、专项算法性能评估、综合压力测试及跨平台兼容性测试的完整实验方案,
具体测试方案实施如下：

（1）基础功能与模块联动验证

测试用例 1（LOD 切换）： 在包含 100 台设备模型的装配车间场景中，操作视点以 2m/s 速度从 50m 外逼近至 5m 处，验证 Web 端基础 LOD 切换功能。测试结果显示，当视距 $\le$ 10m 时系统自动加载面片数 ≥ 5 万的高精度模型且成功率为 100\%。

测试用例 2（模块联动）： 触发 10 台设备同时报警，信息面板与模型高亮效果同步响应率达 98.6\%，平均数据更新延迟 $\le$ 200ms，验证了模型-数据双向绑定机制的可靠性。


（2）融合扫视时序特征的多维感知注视点渲染方法性能验证

测试场景： 在含 100 台动态设备的冲压车间 VR 场景中，用户佩戴头显执行预设的扫视任务，进行 5 分钟连续漫游。

测试用例 1（渲染性能对比）： 对比启用/关闭注视点渲染时的性能差异。通过 Unity Profiler 记录显示，未启用优化时复杂区域帧率波动于 43-52 FPS，GPU 显存占用峰值达 9.8GB；启用融合扫视时序特征的多维感知注视点渲染方法后，帧率稳定于 87-92 FPS，显存占用降至 6.1GB。

测试用例 2（视觉质量评估）： 在扫视着陆后的不同时间窗口内，向中央凹区域注入不同空间频率的模糊刺激，通过 12 名受试者客观辨别任务验证。结果显示，当刺激参数低于 castleCSF-TS 模型预测的感知阈值时，受试者无法区分优化画面与全分辨率画面，客观辨别正确率接近 50\% 随机水平，SSIM 图像质量评估进一步证实焦点区域画质损失率 < 3\%，证明了算法在实现高性能渲染的同时保证了视觉感知的无损性。

（3）基于时空视觉感知的动画网格混合LOD方法验证

测试场景： 在基础场景上添加 5 台包含 200000 个三角面的 AGV，使用 Unity 的 NavMeshAgent 组件实现路径导航，并通过脚本控制其以不同速度运动，验证系统在动态场景下的渲染性能与视觉质量。

测试用例 1（渲染性能对比）：对比启用/关闭动态 LOD 技术的性能差异。测试结果显示，当 AGV 以 5m/s 速度运动时，启用基于时空视觉感知的动画网格混合LOD方法后，平均帧率维持在 85FPS，帧时间标准差从$\pm 4.7$ms 降至 $\pm 2.1$ms；同时，由于对非注视区域 AGV 模型的面片数削减，显存峰值从 12.2GB 优化至 8.7GB，Shader 计算负载降低 28\%。

测试用例 2（视觉质量评估）： 在注视点随目标移动及移开的动态过程中，针对 LOD 连续切换的视觉效果，通过 12 名受试者的主观评分进行验证。结果显示，用户对动态 LOD 过渡的平滑度评分为 4.2/5.0，未报告明显的几何弹出或运动跳变，且 SSIM 均值保持在 0.98 以上，证实了系统能够在大幅降低几何渲染开销的同时，有效维持视觉体验的连续性与无损性。


（4）综合性能与用户体验测试

测试场景： 在基础场景上添加超过30台机械臂与AGV，构建一个几何面片总数超千万的极端复杂环境，评估系统在极限压力下的综合渲染性能与用户体验。

测试用例1（综合性能对比）： 对比四种渲染配置下的关键性能指标：a) 关闭所有优化；b) 仅启用融合扫视时序特征的多维感知注视点渲染方法；c) 仅启用基于时空视觉感知的动画网格混合LOD方法；d) 完整系统即同时启用两项优化技术。结果显示，配置d表现最优，平均帧率达到81.7 FPS，帧时间标准差稳定在3.8ms。在显存占用方面，配置d较配置a降低了35\%。

测试用例2（主观体验评估）： 邀请12名受试者在四种配置下分别完成一套标准化的漫游与视觉搜索任务，任务后使用5点李克特量表对画面流畅度、视觉连续性与整体舒适度进行评分。配置d获得了最高的主观流畅度评分为4.7/5.0。用户反馈表明，完整系统有效减少了画面撕裂感与复杂动画区域的卡顿现象，提升了整体沉浸体验，
验证了本文所提两种渲染优化技术协同工作的有效性，能够在高复杂度工业场景中显著提升系统性能与用户体验。

（5） 跨平台兼容性测试

浏览器测试：桌面端 Chrome（v115+）、Edge（v105+）、Firefox（v110+）、Safari（v16+）及移动端 Safari（IOS 15+）、Chrome（Android 12+）均能稳定运行基础可视化功能。测试中暴露出移动端 Safari 浏览器因 WebGL 性能限制导致模型加载耗时增加 35\% 的问题，后续将进一步优化。另外，受限于 WebGL 2.0 与 GPU 计算需求，大规模场景渲染功能仅限桌面端调用。

操作系统测试：Windows 10/11 与 Ubuntu 22.04 LTS 下 GPU 利用率差异 < 5\%，但 macOS 系统因 Metal API 限制，相同场景显存占用增加 18\%。



\section{本章小结}

本章基于前文提出的融合扫视时序特征的多维感知注视点渲染方法与基于时空视觉感知的动画网格混合LOD方法，设计并实现了一套完整的数字工厂可视化系统。系统采用微服务架构与前后端分离设计，构建了支持 WebGL 轻量化网页浏览与 VR 沉浸式漫游的双模式交互体系，并通过服务层与数据层的高效协作，实现了虚实数据的实时同步与持久化存储。

在系统实现层面，两项核心渲染技术被深度集成于Unity可编程渲染管线：注视点渲染模块依据 castleCSF-TS 感知模型与实时眼动数据，在像素着色阶段动态调整屏幕空间分辨率；动态LOD模块则根据注视位置与时空感知参数，在几何处理阶段对运动设备进行细节的自适应调度。
两者在渲染管线中协同工作，实现了计算资源向视觉关注区域的智能聚焦。

系统测试与验证结果表明，在单场景几何面片总数超千万的高负载环境下，同时启用两项优化技术的系统能够稳定维持81.7 FPS的流畅帧率，GPU显存占用降低35\%以上，且用户焦点区域的视觉质量损失低于3\%。主客观评估验证了该技术在提升渲染效率、保障视觉沉浸感方面的有效性与实用性，为大规模工业数字孪生场景的高性能渲染提供了切实可行的技术解决方案。
