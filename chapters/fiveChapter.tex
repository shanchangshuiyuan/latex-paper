\chapter{数字工厂可视化系统设计与实现}
本章将前文提出的基于眼跳效应的注视点渲染方法与时空感知自适应的动画网格动态LOD技术应用于实际工业场景，设计并实现一套完整的数字工厂可视化系统，通过实际系统的构建与测试，验证两种方法的可行性与有效性。
系统设计支持双模式交互：基于WebGL的轻量级三维可视化与基于VR设备的沉浸式漫游。通过集成本文提出的优化技术，系统能够在保证视觉沉浸感与交互实时性的前提下，显著提升对大规模、高复杂度工厂场景的渲染效率。


\section{系统开发与运行环境}

为保障系统的稳定性、实时性并满足验证算法性能的需求，搭建了以下软硬件开发与测试环境。

\subsection{硬件环境}

核心计算平台配置 Intel Core i7-12700K CPU 与 NVIDIA GeForce RTX 4090 GPU，32GB 内存，确保强大的图形计算与数据处理能力。
VR 部分采用 HTC Vive Pro Eye 头显，其内置的 Tobii 眼动追踪模块为注视点渲染算法提供实时、准确的视线输入，配合 SteamVR 2.0 基站实现精准的空间定位。

\subsection{软件环境}

系统采用前后端分离架构。
前端基于 Vue3 框架与 Three.js 引擎构建 Web 端三维可视化模块；
VR 沉浸模块采用 Unity 2021.3 LTS 引擎开发，并编译为 WebGL 格式嵌入前端。
第三章提出的的 castleCSF-TS 感知模型、动态分辨率渲染算法以及第四章提出的动画网格动态 LOD 算法均以脚本和可编程渲染管线的形式深度集成于 Unity 项目中。
后端服务基于 Node.js 与 Express 框架搭建，负责数据接口、业务逻辑与通信转发。
MySQL 与 InfluxDB 分别用于存储结构化业务数据和时序监控数据。

\section{数字工厂可视化系统设计}

本系统通过浏览器端/服务端体系结构实现，数据处理功能集中在服务器上，浏览器端主要负责场景的渲染、展示和交互，虚拟现实相关的功能在 Unity 中进行开发。

\subsection{系统功能需求}

本文提出的数字工厂可视化系统旨在满足工业场景中三维模型和工厂数据的直观展示与实时交互需求，其功能架构设计需满足多维度感知、高实时性渲染与智能数据分析三大核心要求。
结合人机交互理论和工业数字化技术，并将本文提出的基于眼跳效应的注视点渲染方法与时空感知自适应的动画网格动态LOD技术运用其中，具体需求可归纳为以下方面：

（1）融合感知模型的动态渲染调度：系统必须能够实时接入眼动追踪数据，并依据 castleCSF-TS 模型，动态评估用户在时空维度上的视觉敏感度，从而在渲染管线中实现分辨率与几何细节的实时、自适应调整。

（2）支持动画网格的感知自适应LOD：针对工厂中常见的运动设备如机械臂等，系统需集成时空感知自适应的动画网格动态LOD技术，可根据注视点位置与感知模型输出，对动画网格进行从离线简化到运行时细分的全流程优化，确保在保持注视区域高保真动画细节的同时，高效简化外围区域模型。

（3）支持跨平台的交互模式与数据联动：系统需提供基于网页的轻量级浏览和基于VR头显的沉浸式漫游两种主要交互模式。在网页端，侧重于工厂整体布局与关键指标的快速概览。在VR端，则为用户提供身临其境的第一人称视角。无论何种模式，用户与三维设备的交互如选中、高亮都应实时触发对应的业务数据在可视化面板上的更新，形成闭环。

（4）全面的性能监测与评估能力：为定量验证算法有效性，系统需系统需具备全面的数据采集、分析及性能监控功能，可实时接入工厂实际数据以驱动虚拟场景，同时实时收集并记录帧率、GPU负载、Draw Calls、各优化区域资源消耗等关键指标，并与用户行为数据进行关联分析。


\subsection{系统架构设计}
为满足上述需求，系统采用分层、模块化的微服务架构，如图5.1所示。整体分为数据层、服务层、应用层和渲染引擎层，各层之间通过定义良好的API如RESTful或WebSocket进行通信。

（1）渲染引擎层：该层以Unity实时渲染引擎为框架，深度集成了本文提出的两项核心算法，构成了整个系统的图形处理中枢。它独立负责VR场景的高保真渲染任务，通过WebSocket长连接与服务层进行毫秒级数据同步，实时获取设备状态并反馈用户交互事件。
在此层架构中，我们针对Unity的可编程渲染管线进行了定制开发：基于眼跳效应的注视点渲染方法，被实现为动态分辨率模块，该模块实时处理眼动追踪数据，基于castleCSF-TS感知模型动态生成视觉重要性图谱，并以此指导渲染管线在像素着色阶段实施非均匀的多分辨率渲染。
时空感知自适应的动画网格动态LOD技术被构建为几何处理与网格管理模块，它接收来自注视点渲染模块的视觉重要性图谱和场景上下文信息，在GPU硬件支持下实现从基础LOD选择到自适应细分细化的全流程、感知驱动的几何细节调度。
两个优化模块在渲染管线中协同工作，确保系统能够在高负载渲染场景中，智能地将计算资源聚焦于视觉关注区域，在保证中央凹区域视觉质量的同时，显著降低外围区域的渲染开销，实现了渲染性能与视觉保真度之间的优化平衡。

（2）应用层：该层直接面向终端用户，提供两种互补的交互界面以适配不同使用场景。
Web端基于Three.js构建，侧重于工厂全景的轻量化展示与关键数据监控，用户通过浏览器即可快速访问，实现对工厂运行状态的宏观把握与基础交互。
VR端则作为沉浸式验证平台，完整承载了由Unity编译输出的、集成了所有优化算法的交互环境。用户通过佩戴VR设备进入完全沉浸的第一人称虚拟工厂，其所有视觉体验均深度融入了注视点渲染与动态LOD优化，是评估算法实际体验的核心场景。

（3）服务层：本层作为系统的业务中枢与数据桥梁，基于Node.js微服务架构构建。
其主要职责包括：通过OPC UA、Modbus等工业协议对接物理车间的数据源，将采集到的设备状态、传感器读数等实时信息进行聚合、清洗与转换；
通过RESTful API为Web前端提供结构化的历史数据查询服务；
通过专用的WebSocket服务与VR渲染引擎保持双向、低延迟的实时数据通道，同步设备状态与交互指令；
此外，该层还统一管理用户认证、会话状态及跨端数据同步，确保Web与VR体验间状态的一致性，为上层应用提供稳定、高效的数据服务支撑。

（4）数据层：该层为系统提供统一、可靠的数据持久化支持，采用多类型数据库混合存储方案。
关系型数据库MySQL负责存储工厂模型元数据、用户信息、业务配置等结构化数据。
时序数据库InfluxDB专为处理高速产生的时序数据而设计，用于存储设备实时运行参数、连续的渲染性能指标如帧率、GPU负载以及用户眼动轨迹日志。
此外，文件存储系统用于管理三维模型资产、纹理贴图等大型静态文件。该分层存储策略不仅优化了各类数据的存取性能，也为后续进行深入的算法性能分析及优化系统性能提供了坚实的数据基础。

\section{核心模块实现与算法集成}
数字工厂可视化系统主要由可视化模块、漫游模块、数据通信与监控模块组成，共同构建起虚实结合的工业监控体系。本节将分别详细介绍各个模块的实现，并重点阐述本文所提两大核心技术的集成方式。

\subsection{可视化模块}
可视化模块作为用户交互的核心载体，部署于前端交互层，根据数据类别分为工厂信息可视化和工厂模型可视化，实现了虚实数据的有机整合，模块框架如图 5.2 所示。

在信息可视化层面，基于Vue3框架集成ECharts组件库构建动态数据面板并在页面左右两侧实时展示，通过事件驱动机制实现模型-数据的双向绑定。在模型可视化层面，采用Three.js引擎构建轻量化WebGL场景，结合八叉树空间索引算法实现工厂静态模型的按需加载与LOD切换。

本模块的核心是为VR漫游模块提供基础场景和数据接口支撑，主要的渲染优化验证在集成本文技术的Unity漫游模块中进行。

\subsection{漫游模块}

漫游模块为数字工厂系统提供多维度空间探索能力，支持传统2D屏幕操作与沉浸式VR漫游双模式交互，是验证基于眼跳效应的注视点渲染方法与时空感知自适应的动画网格动态LOD技术有效性的核心载体。模块框架如图5.3所示。


在VR沉浸式体验场景下，系统基于Unity引擎构建了一套独立的、深度定制的高性能渲染管线，以无缝集成并协同调度本文提出的两项核心渲染优化技术。

该渲染管线的运行始于实时数据的获取与处理：系统通过HTC Vive Pro Eye头显内置的眼动追踪模块捕获用户原始的视线数据，并运行高效的眼动事件检测算法，
精准识别出扫视开始、扫视着陆等关键事件，从而确定当前所处的视觉感知窗口，此信息连同场景的亮度、空间频率等特征，共同输入至预置的castleCSF-TS感知模型，
实时计算出当前用户在时空维度上的感知临界空间频率，并据此生成指导整个渲染管线资源分配的核心感知参数。

在像素处理阶段，系统应用基于眼跳效应的注视点渲染方法：依据感知模型输出的参数，管线动态地为屏幕不同区域分配不同的渲染分辨率，
在扫视及随后的视觉敏感度恢复期内，中央凹及周边区域的分辨率将被显著、平滑地调低；
当进入稳定注视期后，则逐步恢复至全分辨率渲染，以此在时间与空间域上消除无效的渲染计算。

在几何处理阶段，系统应用时空感知自适应的动画网格动态LOD技术：针对机械臂等动画网格，渲染管线首先根据注视点位置与模型偏心度，
从预处理生成的多个LOD层级中动态选择一个基础几何体，随后将核心感知参数与模型预计算的顶点重要性图一同传递给GPU的曲面细分着色器，驱动其对基础几何体进行实时、自适应的镶嵌细分。
这使得位于注视中心的动画模型能获得极高的几何细节，而外围模型则保持精简，同时通过过渡混合算法确保了LOD切换的视觉平滑性。

模块通过上述技术，在VR设备上实现稳定了90FPS的流畅漫游体验，同时支持用户眼动、交互行为与场景渲染状态的同步记录，为后续效能分析提供数据基础。


\subsection{数据通信与监控模块}
数据通信与监控模块构建了系统的数据流通管道与性能监控体系，确保系统功能闭环运行，同时为算法有效性验证提供全面的数据支撑。

该模块通过WebSocket协议与服务层构建持久化的双向连接，形成了低延迟的数据流通道。物理工厂侧的实时运行数据包括产线设备状态、各类传感器读数等被持续推送至webGL和Unity渲染引擎，驱动虚拟场景中对应三维模型的动态更新如设备运转动画及报警状态指示等，实现虚实同步。
同时，用户在web端与VR沉浸环境中的所有交互意图如通过手柄点选设备、调整参数、触发操控指令等，也通过同一通道实时上行至服务层，继而触发现实控制系统或业务逻辑的响应，从而完成从用户感知到场景更新的完整闭环。

同时，为了精确评估渲染优化算法的效果，模块深度集成Unity Profiling API，并部署了轻量级自定义性能计数器，对渲染管线的运行状态进行全方位监控。
采集的指标维度包括：渲染帧时间分布、GPU各阶段处理耗时、各分辨率区域的像素填充统计、动画网格LOD切换频率及细分因子分布情况等。所有这些性能数据与精确的时间戳、当前注视点坐标等信息一并打包，通过独立的低优先级WebSocket数据通道传输至服务层，最终持久化存储到时序数据库InfluxDB中。

该模块通过数据管道与Unity引擎、前端界面同步，为工厂运营优化与渲染算法效能评估提供了可靠的数据支撑。

\subsection{系统实现}
本系统通过浏览器登陆访问，首页直观呈现了整体工厂模型，如图5.3所示。
用户可以通过鼠标操作实现对模型的旋转和缩放。为了优化用户体验，系统在初始观察位置较远时优先加载低精度模型，以实现在可接受的延迟内快速渲染；随着观

\subsection{系统测试}
为验证系统核心功能及本文所提两种渲染优化方法的有效性与性能，本节设计了一系列测试用例。
具体测试方案实施如下：

（1）基础功能与模块验证

测试用例 1： 在包含 100 台设备模型的装配车间场景中，操作视点以 2m/s 速度从 50m 外逼近至 5m 处，验证 Web 端基础 LOD 切换与数据面板联动功能。测试结果显示，当视距 ≤ 10m 时系统自动加载面片数 ≥5 万的高精度模型且成功率为 100\%，ECharts 面板在设备选中后数据更新延迟 ≤ 200ms。

测试用例 2： 触发 10 台设备同时报警，信息面板与模型高亮效果同步响应率达 98.6\%，无数据错位或显示延迟现象。


（2）基于眼跳效应的注视点渲染性能验证

测试场景： 在含 100 台动态设备的冲压车间 VR 场景中，用户佩戴头显执行预设的扫视任务即在多个设备间以 2-3 次/秒的频率快速切换注视点，进行 5 分钟连续漫游。

测试用例 1（性能对比）： 对比启用/关闭注视点渲染时的性能差异。通过 Unity Profiler 记录显示，未启用优化时复杂区域帧率波动于 43-52 FPS，GPU 显存占用峰值达 9.8GB；启用基于眼跳效应的注视点算法后，帧率稳定于 87-92 FPS，显存占用降至 6.1GB。

测试用例 2（感知透明性验证）： 在眼跳着陆后的不同时间点，向中央凹区域注入不同空间频率截止的模糊刺激，通过 12 名参与者的主观评分与客观辨别任务验证。结果显示，当刺激参数低于 castleCSF-TS 模型预测的感知阈值时，主观评分与全分辨率条件无显著差异，客观辨别正确率接近 50\% 随机水平，证实了算法的感知无损性。SSIM 图像质量评估进一步证实焦点区域画质损失率 < 3\%。

（3）时空感知自适应的动画网格动态LOD技术验证

测试场景： 在基础场景上添加 5 台包含 20000 个三角面的自动导引运输车模型，使用 Unity 的 NavMeshAgent 组件实现路径导航，并通过脚本控制其以不同速度运动，验证系统在动态场景下的渲染性能与视觉质量。

测试用例 1（渲染效率对比）：对比启用/关闭动态 LOD 技术的性能差异。测试结果显示，当自动导引运输车 以 5m/s 速度运动时，启用时空感知自适应的动画网格动态LOD技术后，平均帧率维持在 82FPS，帧时间标准差从 ±4.7ms 降至 ±2.1ms；同时，由于对非注视区域 AGV 模型的面片数削减，显存峰值从 11.2GB 优化至 8.5GB，Shader 计算负载降低 28\%。

测试用例 2（视觉质量评估）： 邀请12名 用户专注观察某个动画设备，并缓慢将视线从该设备移开。通过主观问卷（5点李克特量表）评估在 LOD 过渡过程中，模型细节变化与运动连贯性是否平滑自然。测试结果显示，用户对动态 LOD 过渡的平滑度评分为 4.2/5.0，未报告明显的几何弹出或运动跳变。然而，当 AGV 速度超过 8m/s 时，模型边缘锯齿化问题逐渐加剧，物体实际物理运动轨迹与渲染位置无法同步，后续需针对性优化。

（4）交互响应测试

测试方法： 模拟 50 次用户通过手柄射线选中设备操作，使用 Wireshark 抓取网络数据包分析延迟。

测试结果： 在局域网环境下，从手柄射线触发至信息面板渲染完成的端到端延迟平均值为 128ms，其中 Unity 事件处理耗时占比 62\%，数据接口响应耗时占比 28\%。在模拟 30\% 网络丢包率的异常条件下，延迟增至 320ms，但系统仍保持功能可用性，未出现崩溃或长时间无响应。

(5) 跨平台兼容性测试

浏览器测试：桌面端 Chrome（v115+）、Edge（v105+）、Firefox（v110+）、Safari（v16+）及移动端 Safari（iOS 15+）、Chrome（Android 12+）均能稳定运行基础可视化功能。测试中暴露出移动端 Safari 浏览器因 WebGL 性能限制导致模型加载耗时增加 35\% 的问题，后续将通过纹理压缩策略进一步优化。另外，受限于 WebGL 2.0 与 GPU 计算需求，大规模场景渲染功能仅限桌面端调用。

操作系统测试：Windows 10/11 与 Ubuntu 22.04 LTS 下 GPU 利用率差异 <5\%，但 macOS 系统因 Metal API 限制，相同场景显存占用增加 18\%。
